## Project overview

Machine-learning evaluation of replacement-heifer selection at a family beef-cattle farm in Bragado, Buenos Aires. The primary deliverable is `notebooks/00_main_pipeline.ipynb`. The actual logic lives in `src/`; notebooks and scripts are thin consumers of that library.

Three-layer analysis:
1. **Outcome prediction** — regression on mean future IHM (Maternal Ability Index, proportion 0–1)
2. **Rule analysis** — programmatic reproduction of the farm's hand-coded rule + concept drift
3. **Rule vs. model comparison** — where disagreements occur, which is more accurate?

## Architecture

### Data flow
```

    └─ src/load.py          → raw DataFrames per sheet
    └─ src/clean.py         → normalize IDVs, labels, IHM scale
    └─ src/lineage.py       → build_cow_registry() → one row per cow, conflict-resolved
    └─ src/events.py        → WhatsApp + IATF event parsing
    └─ src/reproduction.py  → reproductive outcomes
    └─ src/features.py      → build_supervised_dataset() → leakage-safe feature matrix
    └─ src/rules.py         → apply_verdes_rule() / evaluate_rule_reproduction()
    └─ src/models.py        → build_models() → sklearn Pipelines
    └─ src/evaluation.py    → precision@k, regression metrics, ROC-AUC
data/processed/  (committed CSVs — regenerated by pipeline scripts)
outputs/         (figures + tables written by scripts)
```

### Critical domain invariants

**IHM scale**: Old file (`historial_ihm_old`) stores IHM as percent (0–100); new file (`ihm_historico_new`) stores as proportion (0–1). `to_proportion()` in `src/clean.py` handles the boundary at 1.5 — values ≥ 1.5 are divided by 100. IHM = 0.0 is a real observation ("no calf that year"), not missing data.

**Leakage boundary**: A heifer's "selection year" is `birth_year + 2`. Every feature must be derivable from information strictly before that year. See `src/features.py` for how `mother_ihm_at_selection()` and `sire_average_outcome()` enforce this.

**First-year IHM exclusion**: Per the farmer (May 2026), first-year IHM is biased high for vaquillonas. The outcome target uses IHM from age 4+ only (`selection_year + 2`).

**DROP_FEATURES**: `peso_al_nacer` is excluded from all models — it is a constant sentinel (30.0 kg) in the 2017–2022 training window, not a real per-cow measurement. Documented in notebook section 4.5.

**Two labeling schemes**: `verdes` (2025 cohort) and `estrellas` (2027 cohort). They are scheme-equivalent class-by-class (`verdes_3 ≈ estrellas_3`) but the underlying decision criteria evolved (raw → 205-day adjusted IHM). The weight threshold remains 190 kg across both schemes. Cross-scheme comparisons use `to_unified_tier()` but are annotated as tentative in `reports/data_dictionary.md`.

**Registry conflict resolution**: When the same cow appears in multiple source sheets, `build_cow_registry()` applies priority: `terneras_2027 (1) > nacimientos_2025 (2) > terneros_sesiones (3) > vientres (4) > ihm_historico_new (5) > fm_prep_2025 (6)`.

**Rule reproduction accuracy**: The documented verdes rule achieves ~49% label match against the 2025 cohort. Perfect agreement in the top tier (`verdes_3`), significant divergence in lower tiers — the documented rule captures only part of the actual decision logic (see `src/rules.py` module docstring).

### Models
All models are sklearn `Pipeline` objects (`preprocessor → estimator`). Preprocessing: median impute + StandardScaler for numerics; constant-fill impute + OneHotEncoder for categoricals. Candidates: `baseline_mean`, `linear`, `ridge`, `decision_tree`, `random_forest`, `gradient_boost`. Evaluation uses temporal holdout (train on earlier birth cohorts, test on later).

### Tests
36 unit tests in `tests/test_clean.py` cover the normalization layer (`src/clean.py`) only. No tests for the modeling or feature-engineering layers.
